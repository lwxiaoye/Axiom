## 1. 生效与验收边界

前端保存后由 Vite HMR 更新；Python 保存后不会自动进入运行进程，须由跑服务的会话重启 `run.py`。环境变量和依赖变更也不能按前端 HMR 处理。

源码和定向测试证明实现；进程启动与加载检查证明服务版本；真实浏览器任务证明该路径的运行行为。`/health/ready` 成功不能替代后两项，生产发布另按部署手册执行。

---

## 2. 本仓库推荐形态

```text
浏览器 → Vite 本机 :3200（HMR，秒级）
              │
              ├─ /api、/upload  → Java（.env.development / .env.local80）
              └─ /agent-api     → 本机 python -u ./run.py :8000

agent-api / worker
  └─ 日常：agent-api/.venv + python -u ./run.py（同时起 API 和 worker）

OpenSandbox
  ├─ 日常默认：远程 127.0.0.1:8091
  └─ 显式测试：本机 127.0.0.1:8091（需用户授权切换）
```

| 层 | 日常改代码怎么生效 | 不要做 |
| --- | --- | --- |
| 前端 Vue | 跑服务的会话维持 Vite :3200；改代码会话保存即 HMR | 每次 `pnpm build` + 重建 web 镜像 |
| agent-api Python | 改代码会话存盘并说一声；跑服务的会话重启 `python -u ./run.py` | 改代码会话自己 kill :8000；`docker restart` / compose |
| 真正上线 / 给别人看 :80 烤镜像 | 才 `pnpm build` + 按生产手册部署 | — |

改代码会话交付模板：「已改 Python 并存盘，请跑服务的会话重启 `python -u ./run.py`。」

## 3. 一天怎么开（固定口令）

### 3.1 前端热更

```bash
# 仓库根；由跑服务的会话执行
pnpm exec vite --mode development --port 3200 --host
```

浏览器打开：**http://localhost:3200/center/chat**（不是 :80 烤镜像）。
`/agent-api` → `http://127.0.0.1:8000/agent-api`。`build/vite/proxy.ts` 去掉匹配的代理前缀，因此此目标中的 `/agent-api` 必须保留。Java 的 `/api`、`/upload` 以当前启动模式的 `VITE_PROXY` 为准；本次工作区 development 指向办公室 Java，local80 经本机 `19080` 转发。环境文件变更后由跑服务的会话重启 Vite，不能假定旧进程已采用新代理。学校库 / iNode / Clash 排障见 [`处理连接学校VPN的方法.md`](处理连接学校VPN的方法.md)。仓库当前没有 `.env.school`。

### 3.2 后端（本机 venv + run.py）

macOS Homebrew Python 会拒绝系统级 `pip install`（`externally-managed-environment` / PEP 668）。用项目 venv：

```bash
cd agent-api
python3.11 -m venv .venv                 # 仅首次
source .venv/bin/activate
pip install -r requirements.txt          # 仅首次或 requirements 变更
python -u ./run.py                       # 依赖已装好时只跑这一条
```

`run.py` 起 API `:8000` 并监护自己启动的 Worker：每 0.5 秒检查退出，按 1–30 秒退避重启，稳定运行 60 秒后重置退避；关闭启动器时停止该 Worker。本地受管 Worker 缺失时 `/health/ready` 返回 503。命令只由**跑服务的会话**执行。改代码会话存盘后说一声，由这边统一重启。不要 `--break-system-packages`。

启动器先以 `override=False` 读 `.env`，再以 `override=True` 读可选 `.env.han`，API 与 Worker 继承相同环境；`.env.dev` 不参与。默认密钥文件是 `agent-api/data/.connector_key`，在启动子进程前原子初始化。Runtime 地址未显式设置时从 checkpoint 地址派生独立 `agent_runtime` 库；本机运行不意味着使用本机数据库，升级规则见 [`../agent-api/migrations/README.md`](../agent-api/migrations/README.md)。

发布者自用 Agent API 的本地入口同样通过 Vite `/agent-api` 代理：OpenAI 兼容路径为 `/agent-api/openai/v1`。智能体始终发布到广场；在“公开配置”启用 API 与 iframe 后，使用管理页生成的 `axe_` 专用嵌入 Key：URL 形如 `/agent-api/embed/v1/frame/<APP_ID>?embedKeyId=ek_...#embedKey=axe_...`。前半段是可公开的 Key ID，`#` 后的 Key 不会发往服务器；它仍是浏览器可见凭据，必须仅用于受控的白名单站点，不能替代 `axa_`。动态 frame 的 `frame-ancestors` 依赖 API 返回的 CSP，日常本地验证不需要改 Nginx。

### 3.3 一键对照

| 目的 | 命令 |
| --- | --- |
| 前端 | `pnpm exec vite --mode development --port 3200 --host` |
| 后端 | `cd agent-api && source .venv/bin/activate && python -u ./run.py` |
| 依赖变更 | `pip install -r requirements.txt` 后再 run.py |

### 3.4 OpenSandbox

日常固定远程 OpenSandbox（`agent-api/.env` 里的 `127.0.0.1:8091`）。本机覆盖写在 `.env.han`，不要提交。未经用户明确要求不要改沙箱地址。不要用 `scripts/agent-api-docker.sh sandbox` 切模式——那是旧 Docker 流程。

## 4. 什么时候才动 Docker

| 场景 | 动作 |
| --- | --- |
| 日常改 Vue / Python | **不要** Docker；前端 HMR，后端重启 `python -u ./run.py` |
| 改了 `requirements.txt` | venv 里 `pip install -r requirements.txt` 再 `run.py` |
| 用户明确要求服务器/里程碑部署 | 见 [`生产部署手册.md`](生产部署手册.md) |

## 5. 与旧习惯对照

| 旧（已废弃） | 现在 |
| --- | --- |
| Docker 部署员 + `request restart` / drain | 本机 `python -u ./run.py` |
| 改前端 → build → docker build → 起 :80 | Vite :3200 + 本地代理 |
| 改 Python → compose build / docker restart | 重启 `run.py` |
| 用烤镜像验证每一次小改 | 烤镜像只做里程碑 / 演示 |

沙箱默认远程 OpenSandbox（`http://127.0.0.1:8091`）。`run.py` 读 `.env`，可选 `.env.han` 覆盖；**不读** `.env.dev`。

## 6. 给后续 AI / 协作者的硬约定

1. **默认验证入口**：`http://localhost:3200`，不是每次重建 :80。
2. **一个跑服务的会话**统一管 Vite :3200 和 `python -u ./run.py`。改代码会话不要自己重启后端。
3. **改 agent-api 后**：存盘，交付里请跑服务的会话重启 `run.py`。禁止 `docker compose` / `docker restart` / `request restart`。
4. **改前端后**：保存即 HMR；不要主动 `pnpm build` 除非用户要上线包。
5. **OpenSandbox 默认 remote**；未经用户明确要求不要改 `.env` / `.env.han` 里的沙箱地址。
6. 本文件为**开发效率 SSOT**；与 [`主对话-Agent-Harness-架构与开发规范.md`](主对话-Agent-Harness-架构与开发规范.md) 不冲突——Harness 规范管「做什么」，本文管「怎么快验」。
