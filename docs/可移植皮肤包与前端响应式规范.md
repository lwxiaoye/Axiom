# 可移植皮肤包与前端响应式规范

2026-09-11 按皮肤导入器、管理服务和前端外壳核对。包格式以 `agent-api/app/services/campus_assistant/main_chat_skin_package.py` 为校验入口；子智能体复用校验并约束自己的身份字段。以下移动端检查项是验收要求，不等于本次完成了所有视口或真机验证。

## 1. 目标与边界

本规范解决两件事：在开发方系统完成皮肤制作后，把完整成品导出并安装到客户系统；同一份皮肤在桌面、平板和手机上使用，不为移动端重新做一套包。

本轮前端移动端实施范围只覆盖用户实际对话界面：`/center/chat` 与 `/agent/run/:appId`。校园百事通配置和外观工坊只实现皮肤的选择、导入、导出和三端预览；知识库、工作流画布及其他后台页面不在本轮手机验收范围内。

皮肤域分为两类：

| scope | 使用位置 | 管理入口 | 运行时归属 |
| --- | --- | --- | --- |
| `main_chat` | 主对话外壳及校园百事通等复用该外壳的内置应用；当前发布选择来自校园百事通配置 | 主对话皮肤工坊、校园百事通配置 | 主对话声明式渲染器 |
| `sub_agent` | `/agent/run/:appId` | 子智能体外观工坊、智能体配置 | 子智能体运行页渲染器 |

两类包可以遵循相同的文件安全规范，但必须拥有不同的 package kind、导入接口、目录和发布引用。任何跨 scope 导入都必须失败，不能自动转换。

## 2. 包结构

标准扩展名为 `.qzskin`，文件内容是 ZIP：

```text
campus-blueprint-main-v1.qzskin
├── manifest.json
└── assets/
    ├── campus-background.jpg
    ├── backpack.png
    └── student-group.png
```

禁止多层套包、符号链接、绝对路径和 `../`。解压后的文件数不超过 24 个，总大小不超过 12 MiB，单张图片不超过 6 MiB，压缩后与解压后大小比例不得超过 100。

## 3. manifest v1

```json
{
  "kind": "axiom-main-chat-skin",
  "scope": "main_chat",
  "schemaVersion": 1,
  "key": "campus-blueprint-main",
  "version": "1.0.0",
  "name": "校园蓝图",
  "description": "校园百事通迎新主题",
  "renderer": "decorated-chat-v1",
  "assets": [
    {
      "key": "background",
      "path": "assets/campus-background.jpg",
      "mime": "image/jpeg",
      "sha256": "..."
    }
  ],
  "theme": {
    "colors": {
      "page": "#eef6ff",
      "title": "#16324f",
      "body": "#334e68",
      "accent": "#2878d2",
      "composer": "#ffffff",
      "composerBorder": "#bed5ea"
    },
    "composer": {
      "radius": 22,
      "shadow": "soft"
    }
  },
  "layouts": {
    "desktop": {},
    "tablet": {},
    "mobile": {}
  }
}
```

`key` 只允许小写字母、数字和短横线，长度 3–64；`version` 使用 `major.minor.patch`。`main_chat` 在同一租户内 `(key, version)` 唯一；`sub_agent` 是系统全局目录，在整个系统内 `(key, version)` 唯一。内容哈希相同的重复导入幂等返回已有版本，内容不同则冲突。

子智能体包使用同一份 v1 结构，但身份字段必须同时改为：

```json
{
  "kind": "axiom-sub-agent-skin",
  "scope": "sub_agent",
  "renderer": "decorated-agent-run-v1"
}
```

这三个字段是一组，不允许只改其中一个。客户导入后，系统生成不超过 64 字符的稳定 `assignmentKey` 给工作流草稿/发布记录引用；导出仍保留包内的 `key + version`，因此不依赖客户数据库 ID。

## 4. 声明式布局

`decorated-chat-v1` 只接受以下布局对象：

```json
{
  "background": {
    "asset": "background",
    "fit": "cover",
    "position": "center-bottom",
    "opacity": 1
  },
  "content": {
    "maxWidth": 920,
    "topGap": 120
  },
  "decorations": [
    {
      "asset": "backpack",
      "anchor": "composer-top-left",
      "width": 88,
      "x": 18,
      "y": 1,
      "opacity": 1,
      "visible": true
    }
  ]
}
```

允许的锚点为 `page-top-left`、`page-top-right`、`page-bottom-left`、`page-bottom-right`、`intro-top`、`composer-top-left`、`composer-top-right`。`x/y` 限制在 -240–240，宽度限制在 16–480，透明度限制在 0–1。所有装饰层都由统一渲染器强制 `pointer-events:none`、限制层级并裁剪溢出，manifest 不能传选择器、CSS 属性名或 HTML。

三端布局采用“完整设备布局”而不是运行时猜测。导出器必须确保 desktop、tablet 和 mobile 三个键都存在；每端最多 8 个装饰元素。手机端必须满足：内容区不产生横向滚动、输入框和发送/停止按钮不被遮挡、正文最小可读宽度 280px、点击目标至少 44×44 CSS px。

## 5. 素材安全

v1 只允许 PNG、JPEG 和 WebP。服务端必须同时校验扩展名、声明 MIME、文件魔数、图片解码结果和像素上限；禁止 SVG、GIF、字体、视频、HTML、CSS 和任何可执行文件。图片总像素不超过 32 MP，单边不超过 8192 px。

manifest 的每个素材都必须存在且 SHA-256 相符；ZIP 中未被 manifest 引用的文件、重复规范化路径、大小写碰撞路径和隐藏文件均拒绝。导出时从持久化字节重新计算哈希，不信任数据库中的旧声明。

## 6. 导入、安装、发布和导出

1. 导入阶段在内存或隔离临时目录读取 ZIP，先做压缩安全、manifest schema、scope、renderer、图片解码和哈希校验。
2. 校验通过后以单个数据库事务写入不可变皮肤版本和素材；任一步失败不得留下半套皮肤。
3. v1 只接受完整包：缺失任意一端布局或 renderer 不匹配时整包拒绝，不写入数据库；校验完成的版本直接进入 `active`。
4. 校园百事通草稿只允许选择当前租户可见、`scope=main_chat`、`status=active` 的版本；发布快照固定保存版本 ID，后续导入同 key 新版本不能偷偷改变线上页面。
5. 导出按版本 ID 从数据库读取 manifest 和素材重新组包，重算哈希并生成规范化 ZIP；不得读取开发机源码目录或前端 import。
6. `sub_agent` 导入后进入全局皮肤库，不携带租户归属，不需授权记录；所有子智能体试衣间直接读取同一目录。
7. `main_chat` 中正在被草稿或已发布配置引用的版本不可删除。`sub_agent` 允许管理员删除正在使用的版本，但必须在同一个数据库事务内先将草稿定义、草稿分配和已发布分配改为系统默认外观，再删除或撤下皮肤包。已发布 JSON 和历史版本不改写，以保持发布审计链。

### 6.1 管理端 CRUD 语义

`main_chat` 和 `sub_agent` 分别提供自己的管理接口与界面，不合并两类目录。两类都按以下语义实现：

1. **新增**：导入一个完整、经验证的新版本。相同内容哈希幂等返回既有版本。
2. **查询**：列表和详情返回包身份、安装状态、来源、可安全预览的 manifest 与引用状态；导出是查询指定版本的完整字节交付。
3. **修改**：只允许更新当前系统中的显示名称和管理备注。manifest、素材、布局、主题、key、version 和 content hash 不可原地修改；这些内容变更时必须提高版本号后重新导入。导出包仍保留原始不可变 manifest，本地管理备注不混入可移植内容哈希。
4. **删除**：`main_chat` 仍执行引用保护，被草稿或发布配置引用时返回明确冲突。`sub_agent` 删除时锁定皮肤版本，事务性地将 `AgentPresentationAssignment` 的草稿/已发布分配和当前 `WorkflowDefinition.draft_json` 中匹配的外观改为 `default`，然后再删包。`WorkflowDefinition.published_json` 与不可变的历史 `WorkflowVersion` 不改写，以保持 `published_version` 的审计链；当前线上页由已发布分配立即回退，历史页在安装版本已不存在时由运行时安全回退系统默认外观。用户导入的版本同时删除持久素材；随应用交付的皮肤包保留不可见的撤下记录，避免目录刷新后被自动装回，并允许管理员通过显式重新导入恢复。

## 7. 前端响应式基线

统一断点：

| 模式 | CSS 视口 | 目标 |
| --- | --- | --- |
| desktop | `>= 1024px` | 完整导航和多栏工作区 |
| tablet | `720–1023px` | 折叠导航、单主栏、次要面板抽屉化 |
| mobile | `< 720px` | 单栏、底部/抽屉导航、44px 触摸目标、支持安全区 |

本轮只约束 `/center/chat` 和 `/agent/run/:appId`。两页必须避免固定页面宽度和横向正文滚动，不得依赖 hover 作为唯一操作；固定底部输入框必须加 `env(safe-area-inset-bottom)`，虚拟键盘出现时不得遮住当前输入和发送按钮。子智能体左栏在手机端变为会话抽屉，右栏变为底部面板，默认均收起。当前 `center.vue` 的紧凑主导航是带遮罩的侧边抽屉，历史记录使用独立抽屉，并非底部导航；皮肤三端布局断点与对话外壳的紧凑模式断点应分别读取对应实现。

校园百事通配置与外观工坊只要求管理功能在当前后台布局中可用，并提供 desktop/tablet/mobile 三档预览；本规范不据此宣称知识库、工作流画布、系统管理等后台页面已经完成手机适配。

## 8. 验收矩阵

每套皮肤和关键页面至少验证以下视口：`1440×900`、`1024×768`、`768×1024`、`390×844`、`360×800`，并补一次手机横屏。验收同时覆盖空白态、已产生消息、生成中、错误/HITL、长文本、键盘焦点、侧栏/抽屉和导入导出回读。

“代码里有媒体查询”不算完成；必须有实际浏览器截图或自动化断言证明无关键遮挡、无意外横向滚动、主操作可触达，且导出包在另一份空系统中重新导入后素材可加载。
