本文说明当前工作流编排器中可使用的节点。节点名称、类型和可用范围以
`src/views/workflow/core/templates.ts` 与
`src/views/workflow/core/parity.manifest.json` 为准。

2026-09-11 复核文档入口与源码边界。节点截图是制作文档时的界面记录，不保证后续样式逐像素一致；外部工具、应用和账号权限决定的动态实例应在当前目录查询。

## 使用约定

- **连线方向**：从上游节点右侧输出连到下游节点左侧输入。只有已连通的上游节点输出，才可在下游配置中引用。
- **变量引用**：文本、请求参数等支持选择上游输出或全局变量；节点被删除后，应检查并清理失效引用。
- **错误处理**：HTTP 请求、代码运行等节点发生错误时，先在调试中查看错误信息；开启错误捕获后可把错误分支接到指定回复或降级逻辑。
- **发布前调试**：涉及模型、外部 HTTP、工具、代码、循环或并行时，至少完成一次调试运行，确认必填输入、变量类型和输出结构。
- **固定节点**：系统配置、流程开始及循环体开始由系统维护，不能作为普通节点删除或复制。

## 新手先理解：一个工作流如何运行

工作流不是把节点“摆在画布上”就会运行。一次用户提问会从“流程开始”进入，只沿着**已连通的连线**执行；每个节点把自己的输出交给下游节点，最终由“指定回复”或 AI 对话把结果呈现给用户。

```text
用户输入
  → 流程开始（产生“用户问题”）
  → 处理节点（AI / 知识库 / HTTP / 代码 / 判断）
  → 指定回复（把结果返回给用户）
```

牢记两个概念：

| 概念 | 解决的问题 | 示例 | 缺失时的表现 |
| --- | --- | --- | --- |
| 连线 | 哪些节点会按什么顺序执行 | 流程开始 → AI 对话 → 指定回复 | 节点不执行，或发布时提示不可达。 |
| 变量引用 | 节点执行时读取什么数据 | AI 对话的“用户问题”选择流程开始的输出 | 节点执行了，但拿到空值、默认值或错误数据。 |

通常同时需要两者。例如“AI 对话”已连到“指定回复”，只表示指定回复会执行；还要在“回复内容”里引用 AI 的`AI 回复内容`，用户才能看到模型生成的答案。

## 五分钟完成第一个可运行流程

目标：用户提出问题后，AI 直接回答。

1. 新建工作流后保留系统已有的“流程开始”节点，点击“添加节点”，依次加入“AI 对话”和“指定回复”。
2. 连线：从“流程开始”右侧输出拖到“AI 对话”左侧输入；再从“AI 对话”连到“指定回复”。
3. 配置 AI 对话：选择可用模型；在“用户问题”字段使用变量选择器选择“流程开始 / 用户问题”；可填写提示词，例如“请使用简洁、准确的中文回答校园服务问题”。
4. 配置指定回复：在“回复内容”字段选择“AI 对话 / AI 回复内容”。
5. 点击“调试”，输入“图书馆周末几点关门？”。预期：AI 对话有文本输出，指定回复显示同一段内容。
6. 调试成功后再保存草稿、运行预览，并完成发布前检查。

这个最小流程不需要知识库、HTTP 或代码节点。先确认它能稳定回答，再逐步增加检索、表单和业务接口，问题更容易定位。

## 变量选择与数据类型

### 推荐的引用方式

不要手写节点 ID。点击输入框中的变量选择器，依次选“上游节点 → 输出字段”，编辑器会插入正确的引用。文本框中常见的结果为：

```text
{{node:<节点ID>:<输出key>}}
```

全局变量使用：

```text
{{变量key}}
```

节点复制、删除或重新创建后，节点 ID 可能变化；用选择器重新选择一次比手工修改引用可靠。

### 先看类型，再传下游

| 上游输出 | 正确下游用法 | 常见误用 |
| --- | --- | --- |
| `String`，如用户问题、AI 回复 | 用于提示词、指定回复、URL 参数、代码输入 | 把空文本当成对象字段读取。 |
| `Object`，如表单结果、HTTP JSON | 在代码中读取字段，或先声明所需动态字段 | 直接拼到提示词，导致得到一段不可控 JSON。 |
| `Array`，如文件列表、查询结果 | 交给循环/并行节点，逐项处理 | 传给只能接受单个文本的字段。 |
| `DatasetQuote`，知识库引用 | 传给 AI 对话或引用合并节点的“知识库引用”字段 | 当普通文本拼接到提示词。 |
| `ChatHistory`，新的上下文 | 传给下一轮 AI 对话或问题优化的“聊天记录”字段 | 手工转成字符串后再作为历史传入。 |

## 调试：按节点检查，不要只看最终回复

1. 点击“调试”，准备一条能覆盖当前分支的真实测试问题；涉及表单时填写测试值，涉及 HTTP 时使用安全的测试参数。
2. 从“流程开始”开始逐节点查看执行记录，先确认输入是否符合预期，再确认输出字段和类型。
3. 第一个输入或输出异常的节点，通常就是问题所在；不要只修改最终“指定回复”。
4. HTTP 节点重点核对 URL、请求方法、鉴权、请求体、超时、状态码和响应 JSON；代码节点重点核对入参名、`return` 的 key 与声明输出字段是否一致。
5. AI 节点重点核对模型是否可用、用户问题是否已引用、知识库是否已选择、提示词是否过长或约束矛盾。

## 发布前检查清单

- [ ] 从“流程开始”到最终回复的每个业务节点都有连线，没有孤立节点。
- [ ] 所有带 `*` 的必填字段已填写；模型、用户问题、循环数组和 HTTP URL 尤其需要检查。
- [ ] 下游变量引用的来源节点已连通，且类型匹配。
- [ ] 表单字段的 `key` 唯一且稳定；代码 `return` 的 key 与输出字段一致。
- [ ] 知识库、Skill、工具、子应用和 HTTP 接口在当前账号下具有可用权限。
- [ ] 循环和并行任务有明确输入、有限并发和可结束条件；没有并发写同一全局变量。
- [ ] 外部 HTTP、代码、模型调用存在用户可理解的失败回复或降级分支。
- [ ] 已完成至少一次调试和一次运行预览，确认用户能看到最终回复。

## 高频故障排查

| 现象 | 常见原因 | 先做什么 |
| --- | --- | --- |
| 变量选择器里找不到上游字段 | 两个节点未连通，或上游未声明动态输出字段 | 先补连线；在表单、HTTP、代码节点中定义并命名输出字段。 |
| 节点执行了但结果为空 | 引用错字段、上游值为空或类型不匹配 | 在调试记录中查看该节点实际输入值。 |
| AI 不回复或回答偏题 | 未引用用户问题、模型不可用、提示词冲突、知识库引用不匹配 | 先用最小 AI 流程验证模型和用户问题，再加其他能力。 |
| HTTP 请求失败 | URL、方法、鉴权、请求体、超时或响应结构不符合预期 | 查看状态码和原始响应；先用小数据测试接口。 |
| 代码节点没有预期输出 | `return` 的 key 与输出字段名不同 | 让 `return { result: value }` 与声明的 `result` 输出字段完全一致。 |
| 循环无法结束或结果错乱 | 输入不是数组、没有跳出条件、并发分支共享变量 | 先打印/查看数组结构，限制并发，并将聚合结果作为唯一输出。 |

## 输入、输出与变量引用

### 通用配置步骤

1. 从“添加节点”放入节点并完成连线；只有已连通的上游节点输出，才能在下游变量选择器中正常引用。
2. 单击节点，在节点配置卡片或右侧配置区域填写字段。标有 `*` 的字段为必填项；模型、URL、循环数组、用户问题等缺失会导致调试或发布失败。
3. 固定值可直接输入；需要使用上游数据时，点击字段中的变量选择器，选择“节点输出”或“全局变量”。不要手写节点 ID。
4. 表单输入、代码运行、HTTP 请求等动态节点，应先新增并命名输出字段，再让下游节点引用该字段。
5. 文本模板中的普通节点引用形如 `{{node:<节点ID>:<输出key>}}`，全局变量形如 `{{key}}`。实际使用以变量选择器插入的内容为准，避免节点复制后引用 ID 不一致。
6. 使用“调试”验证一条真实输入，重点查看节点执行记录中的输入值、输出值和错误信息；确认无误后再保存草稿或发布。

### 输出类型与连线原则

| 类型 | 常见来源 | 可接收的典型节点 | 配置要点 |
| --- | --- | --- | --- |
| `String` | 用户问题、AI 回复、文本拼接、表单字段 | AI 对话、指定回复、HTTP、代码、判断器 | 文本模板可直接插入；空值要给默认处理。 |
| `Number` / `Boolean` | 循环下标、代码输出、判断器数据 | 判断器、代码、变量更新 | 比较时保持类型一致，避免把数字当普通字符串比较。 |
| `Object` | 表单结果、代码返回、HTTP JSON | 代码、HTTP、变量更新、下游动态节点 | 若下游需要单字段，应先声明或提取该字段。 |
| `Array` | 循环输入、知识库引用集合、HTTP/代码结果 | 循环、并行执行、代码 | 先确认数组元素结构；并行或循环中不要依赖共享写入顺序。 |
| `Any` | 工具原始响应、当前循环元素 | 代码、文本模板、动态工具 | 先在调试记录确认实际数据结构，再传给严格字段。 |
| `ChatHistory` | AI 对话的新上下文 | 后续 AI 对话、问题优化、工具调用 | 使用“聊天记录”字段，不要拼接成普通字符串。 |
| `DatasetQuote` | 知识库搜索、知识库引用合并 | AI 对话、知识库引用合并 | 使用“知识库引用”字段；它不是普通文本。 |

### 各节点输入输出速查

下表列出编辑器中的主要配置项、可供下游使用的结果，以及一条可对照变量选择器填写的示例。动态节点的字段名会随所选工具或应用变化，应以节点表单为准。

| 节点 | 关键输入 / 配置 | 主要输出或控制结果 | 输入 → 输出示例 |
| --- | --- | --- | --- |
| 系统配置 | 开场白、全局变量、语音、问题引导、文件上传开关 | 全局变量；开启文件能力后流程开始可提供用户文件。 | 设置全局变量 `school=清竹学院` → 文本节点可引用 `{{school}}`。 |
| 流程开始 | 无业务输入 | `用户问题`（`String`）；按系统配置提供用户文件。 | 用户输入“图书馆周末几点关门？” → `用户问题`输出同一文本。 |
| AI 对话 | 模型、提示词、聊天记录、知识库、Skill、文件链接、用户问题 | `AI 回复内容`（`String`）、`新的上下文`（`ChatHistory`）。 | 用户问题 + 知识库引用 → “图书馆周末 21:00 闭馆。” |
| 知识库搜索 | 知识库、检索问题、引用上限、检索/重排序/问题优化策略 | `知识库引用`（`DatasetQuote`）。 | 检索问题“奖学金评定条件” → 命中的制度分段引用集合。 |
| 知识库引用合并 | 多路知识库引用、合并上限 | 合并后的 `知识库引用`。 | 制度库引用 + FAQ 引用 → 一组截断后的统一引用。 |
| 问题分类 | 模型、业务背景、分类项 | `分类结果`及对应分类出口。 | “怎么续借图书？” → `分类结果=图书借阅`，进入该分支。 |
| 文本内容提取 | 模型、待处理文本、字段 key/说明/必填规则 | `提取是否完整`、完整结果及按字段 key 生成的动态输出。 | “9月1日至3日请假” → `startDate=2026-09-01`、`endDate=2026-09-03`。 |
| 问题优化 | 模型、聊天记录、当前问题、改写背景 | 优化后的问题（`String`）。 | 历史“图书馆几点关门？” + 当前“周末呢？” → “图书馆周末几点关门？”。 |
| 指定回复 | 回复文本或上游变量 | 向用户发送回复；通常作为流程可见结果。 | `回复内容={{node:<AI节点ID>:answerText}}` → 将 AI 回复展示给用户。 |
| 用户选择 | 提示语、选项 | 用户选择值和对应选项出口。 | 选项“查询借阅记录 / 查询续借规则” → 用户点“查询续借规则”。 |
| 表单输入 | 说明文案、字段标签、`key`、类型、必填、默认值、校验规则 | 每个字段的动态输出，以及 `表单结果`（`Object`）。 | 姓名 `name=张三`、班级 `class=计科1班` → `{name:"张三",class:"计科1班"}`。 |
| 自定义反馈 | 反馈文本或变量 | 反馈记录；不作为模型上下文。 | 输入“用户选择人工服务” → 记录该反馈，不追加到 AI 聊天记录。 |
| HTTP 请求 | 自定义输入、方法、URL、超时、请求头、鉴权、Query、Content-Type、请求体、声明的输出字段 | 原始响应、错误信息及配置的动态字段。 | `userId=1001` 代入 `/users/{{userId}}` → 输出 `{name:"张三"}`或声明的 `name` 字段。 |
| 文本拼接 | 文本模板、节点输出、全局变量 | 拼接文本（`String`）。 | `{{school}} 的 {{name}} 同学，你好` → “清竹学院的张三同学，你好”。 |
| 变量更新 | 目标变量、更新方式、更新值 | 更新后的变量值。 | `status`赋值为`completed` → 后续节点读取 `status=completed`。 |
| 文档解析 | 文件链接列表 | 解析文本或文件处理结果。 | 上传的 `notice.pdf` 文件链接 → 解析出的正文文本和原始处理结果。 |
| 工具调用 | 模型、提示词、聊天记录、文件链接、用户问题、挂载工具 | `AI 回复内容`、`新的上下文`和工具循环结果。 | “现在几点？” + 挂载当前时间工具 → 调工具后回复当前日期时间。 |
| 停止工具循环 | 目标工具的执行结果 | 结束工具循环并返回当前工具结果。 | 当前时间工具已返回结果 → 停止继续选工具，以该结果结束循环。 |
| 工具参数 | 参数名、类型、说明、变量来源 | 覆盖后的工具入参。 | 设定 `city=郑州` → 天气工具收到固定城市参数。 |
| 代码运行 | 自定义输入、运行语言、脚本、显式声明的输出字段 | 声明字段、完整返回对象和错误信息。 | 输入 `data1=[1,1,2]`，`return {result:[1,2]}` → 输出 `result=[1,2]`。 |
| 判断器 | 条件组、比较方式、默认分支 | 命中的分支出口。 | `score >= 60`且分数为`85` → 从“通过”出口继续。 |
| 循环节点 | 循环模式、数组/条件、聚合输出 | `循环结果数组`和错误信息。 | 输入 `[{id:1},{id:2}]` → 两轮执行后输出两个元素的聚合结果。 |
| 循环体开始 | 由循环节点自动注入 | `当前下标`、`当前元素`、`当前循环次数`。 | 第一轮数组循环 → `当前下标=0`、`当前元素={id:1}`、`当前循环次数=1`。 |
| 跳出循环 | 无业务字段 | 终止当前循环容器。 | 判断当前元素已匹配目标 → 触发跳出，不再处理后续元素。 |
| 并行执行 | 输入数组、最大并发、重试次数、聚合输出 | 成功结果、完整结果、整体完成状态。 | 同时解析 `a.pdf`、`b.pdf` → 输出两份解析结果及完成状态。 |
| 单工具实例 | 由所选工具 schema 生成的参数 | 工具 schema 定义的返回字段。 | 当前时间工具输入 `日期格式=yyyy-MM-dd` → 输出格式化日期或原始响应。 |
| 工作流工具 | 目标工作流工具的动态 schema | 工具公开的动态返回字段。 | 传入 `city=郑州` → 工作流工具返回其定义的天气/路线等字段。 |
| 子应用 | 目标应用的动态 schema | 应用公开的动态返回字段。 | 传入 `question=如何请假` → 子应用返回回答文本或业务结果。 |
| 自主 Agent | Agent 编辑器自动生成 | Agent 运行结果；不在普通节点菜单中手动创建。 | 用户问题 + Agent 的模型/工具策略 → Agent 规划并输出最终回答。 |

### 高频节点的配置方式

#### AI 对话：知识库问答

1. 将“流程开始”的`用户问题`连到 AI 对话，或在“用户问题”字段选择该输出。
2. 选择已配置且可访问的模型，填写只描述角色、边界和回答要求的提示词。
3. 在“知识库”中选择一个或多个知识库；需要更强可控性时，先用“知识库搜索”节点，再把其`知识库引用`传入 AI 对话。
4. “聊天记录”填写保留轮数，例如 `6`；多轮问答应引用上游 AI 的`新的上下文`，而不是自行拼接历史文本。
5. 将`AI 回复内容`引用到“指定回复”。若回答必须结构化，先用“文本内容提取”或代码节点处理后再回复。

#### 表单输入：先定义 key，再引用结果

1. 填写说明文案，新增表单项；为每项配置标签、唯一且稳定的`key`、描述、默认值、最大长度和必填规则。
2. `key`是下游变量名，例如姓名用 `name`、班级用 `class`；不要仅依赖可修改的显示标签。
3. 下游需要单字段时选择对应的动态输出；需要整份表单时选择`表单结果`（`Object`）。
4. 例如指定回复可引用 `{{node:<表单节点ID>:formInputResult}}`；实际生产文案通常应先通过文本拼接或代码节点格式化。

#### HTTP 请求：把变量作为受控输入传入

1. 先用“自定义输入”定义本节点可用的变量，并将其分别绑定到上游输出或默认值。
2. 选择请求方式，填写 URL 和超时时间；在 Query、请求头或 JSON 请求体中引用这些变量。常见形式为 `{{变量名}}`。
3. 根据接口要求设置鉴权和 `Content-Type`；密钥使用受控配置，禁止直接写在可见的业务文案或回复里。
4. 为下游需要的响应字段新增输出字段，并在调试中核对状态码、响应结构和字段值；失败时接入明确的降级分支。

#### 代码运行、循环与并行：先约定数据契约

1. 代码节点的“自定义输入”定义函数入参；脚本 `return` 的 key 必须与已声明输出字段完全一致，例如 `return { result: data }` 对应输出字段 `result`。
2. 循环节点选择“数组循环”时传入 `Array`，在循环体开始节点使用`当前元素`和`当前下标`；需要汇总时配置聚合输出，最后从`循环结果数组`读取。
3. 并行执行只用于彼此独立的数组任务，设置保守的最大并发和重试次数；不要让多个并发分支更新同一全局变量。
4. 在接入外部 HTTP、工具或模型前，先用一条小数据在调试中验证每轮的输入输出，避免批量执行后才发现字段名或类型错误。

## 系统节点

### 系统配置（`userGuide`）

![系统配置节点面板](./images/workflow/nodes/system-config.png)

**用途**：配置应用级能力，而非处理单次请求。可设置开场白、全局变量、问题引导、快捷对话、语音能力和用户文件开关。

**关键配置**：

- 需要让后续节点读取用户上传文件时，先开启文件能力；流程开始节点才会提供用户文件输出。
- 全局变量适合保存整个流程共享的默认值、开关或业务常量，不应用于保存单次临时处理结果。

**注意事项**：这是固定节点，没有输入输出连线；它不代表工作流的执行起点。

### 流程开始（`workflowStart`）

![流程开始节点面板](./images/workflow/nodes/workflow-start.png)

**用途**：工作流的唯一入口，接收用户问题并向下游提供可引用变量。

**主要输出**：`用户问题`；启用系统配置中的文件能力后，还会提供用户上传的文件。

**常见用法**：将“用户问题”连接或引用到 AI 对话、知识库搜索、问题分类、问题优化等节点。

**注意事项**：该节点固定存在且不能删除。所有实际业务节点应从它开始连通，否则发布校验会认为节点不可达。

## AI 与知识库节点

### AI 对话（`chatNode`）

![AI 对话节点面板](./images/workflow/nodes/ai-chat.png)

**用途**：调用大模型生成一轮回答，也可以作为工具调用循环中的模型决策节点。

**关键配置**：选择模型；填写系统提示词；设置历史轮数；按需关联知识库、Skill、文件链接和用户问题。

**主要输出**：`AI 回复内容`、`新的上下文`，以及在模型支持时的思考过程。

**示例**：流程开始的用户问题 → 知识库搜索 → AI 对话。将检索到的引用与用户问题一起传给 AI 对话，使回答有依据。

**注意事项**：模型、上下文和引用内容都会影响成本与响应时间。模型输入应尽量来自明确的上游节点，避免把无关长文本全部拼入提示词。

### 知识库搜索（`datasetSearchNode`）

![知识库搜索节点面板](./images/workflow/nodes/dataset-search.png)

**用途**：在选定知识库中检索与问题相关的分段。

**关键配置**：关联至少一个知识库；设置检索问题、相似度阈值、检索模式、语义与关键词权重，以及是否启用重排序或问题优化。这些检索参数会随请求传入知识库服务。

**主要输出**：`知识库引用`，可接入 AI 对话或知识库引用合并。

**示例**：将流程开始的用户问题作为检索问题，检索后把引用交给 AI 对话。

**注意事项**：检索问题应是自然语言问题而不是整段提示词；引用上限过大可能稀释重点并增加模型输入长度。

### 知识库引用合并（`datasetConcatNode`）

![知识库引用合并节点面板](./images/workflow/nodes/dataset-concat.png)

**用途**：合并多个知识库搜索节点的引用，并按统一 Token 上限截断。

**关键配置**：选择多个引用来源，设置合并后的引用上限。

**主要输出**：合并后的`知识库引用`。

**示例**：分别检索“制度库”和“问答库”，将两路结果合并后再传给 AI 对话。

**注意事项**：只接收知识库引用类型的输出；不要把普通文本直接当作引用来源。

### 问题分类（`classifyQuestion`）

![问题分类节点面板](./images/workflow/nodes/classify-question.png)

**用途**：由模型识别问题所属类别，并从对应的分支继续执行。

**关键配置**：选择分类模型；填写业务背景；设置分类项。每个分类项都有独立的右侧分支出口。

**主要输出**：`分类结果`。

**示例**：设置“招生咨询”“图书借阅”“其他问题”三个分类，分别接到不同知识库或指定回复。

**注意事项**：分类项应互斥且命名清楚；必须为兜底类别连线，否则未命中预期分类时流程可能没有后续处理。

### 文本内容提取（`contentExtract`）

![文本内容提取节点面板](./images/workflow/nodes/content-extract.png)

**用途**：利用模型从非结构化文本中提取指定字段。

**关键配置**：选择提取模型；写明提取要求；输入待处理文本；配置字段 key、描述和必填要求。

**主要输出**：`提取是否完整`、完整提取结果、各动态字段输出。

**示例**：从请假申请文本中提取开始时间、结束时间和请假原因，再将字段交给 HTTP 请求节点。

**注意事项**：字段描述要给出清楚格式，如日期格式或枚举范围；必填字段缺失时应按“提取是否完整”设计降级分支。

### 问题优化（`cfr`）

![问题优化节点面板](./images/workflow/nodes/question-rewrite.png)

**用途**：结合历史对话，把用户问题改写为更适合检索的独立问题。

**关键配置**：选择模型，传入聊天记录和当前问题，按需要填写改写背景。新建节点默认携带最近 3 轮历史，并将改写输出限制为 128 tokens，以降低该额外模型调用的延迟；需要更长上下文时可按节点单独调大。

**主要输出**：优化后的检索问题数组，始终包含原问题。默认最多 4 条、可配置为 1～8 条；若用户一句话中包含多个独立问题，按地址、流程、人员等事实目标分别生成查询，并保留年级、校区、时间等限定条件。

**示例**：用户先问“图书馆几点关门”，再问“周末呢”；将第二句优化为带有图书馆上下文的完整检索问题。

**注意事项**：它用于提升检索质量，不等于直接生成最终回答；通常接在知识库搜索前。知识库搜索会分别检索数组中的每一条问题，并轮流保留各查询的高相关引用，避免前几个问题占满引用上限；不要把该输出连接到 AI 对话的“用户问题”。每增加一条检索问题都会增加一次知识库请求，建议按问题复杂度设置上限。

## 交互与回复节点

### 指定回复（`answerNode`）

![指定回复节点面板](./images/workflow/nodes/answer.png)

**用途**：立即向用户返回固定文本或上游变量内容。

**关键配置**：填写回复内容，或引用上游变量。引用变量时，上游值会覆盖手工填写的文本。

**示例**：判断器命中“服务维护”后，直接回复维护通知；或输出 HTTP 接口返回的查询结果。

**注意事项**：它适合作为一个用户可见的结束或阶段性回复节点；回复中不要暴露内部接口密钥、调试信息或原始异常。

### 用户选择（`userSelect`）

![用户选择节点面板](./images/workflow/nodes/user-select.png)

**用途**：让流程暂停，显示多个选项并等待用户点击后继续。

**关键配置**：设置提示语和选项。每个选项对应一个独立的后续分支。

**主要输出**：用户选择的值。

**示例**：让用户选择“查询借阅记录”或“查询续借规则”，分别进入不同流程。

**注意事项**：这是交互节点，需要运行时支持暂停与恢复；每个选项都应连接下游，且应考虑用户取消或无有效选择的处理。

### 表单输入（`formInput`）

![表单输入节点面板](./images/workflow/nodes/form-input.png)

**用途**：暂停流程，向用户收集多个结构化字段后继续。

**关键配置**：设置表单标题、说明、字段名称、字段类型、必填规则和默认值。

**主要输出**：表单字段值。

**示例**：提交报修前收集地点、设备类型、故障描述和联系电话。

**注意事项**：字段 key 是后续引用的稳定标识，创建后不要随意改名；敏感信息应遵循业务数据保护要求。

### 自定义反馈（`customFeedback`）

> 当前基础节点菜单没有该节点的创建入口；它保留用于已有工作流的兼容执行。截图不能替代真实的运行时面板，恢复为可新建节点后再补充该节点的现场截图。

**用途**：记录一条反馈文本，不将其加入模型上下文。

**关键配置**：填写或引用反馈内容。

**示例**：在重要分支完成后记录“用户选择了人工服务”用于后续运营分析。

**注意事项**：它不是面向用户的回复节点，也不能替代审计或持久化业务日志。

## 数据处理节点

### HTTP 请求（`httpRequest468`）

![HTTP 请求节点面板](./images/workflow/nodes/http-request.png)

**用途**：调用外部 REST/HTTP 服务，并将响应传给后续节点。

**关键配置**：配置请求方法、URL、请求头、查询参数、请求体、鉴权和响应字段提取；可在参数中引用上游变量。

**主要输出**：响应数据、按 JSONPath 配置的动态提取字段，以及错误信息。

**示例**：文本内容提取 → HTTP 请求，将提取出的工单字段提交至业务系统。

**注意事项**：密钥应使用受控配置或密钥字段，不要写入可见文本；先在调试中验证 URL、超时、响应码和 JSONPath。失败分支应给出用户可理解的降级回复。

### 文本拼接（`textEditor`）

![文本拼接节点面板](./images/workflow/nodes/text-editor.png)

**用途**：将固定文案和多个上游变量拼成一段文本。

**关键配置**：输入文本模板，在需要的位置插入上游变量或全局变量。

**主要输出**：拼接后的文本。

**示例**：将姓名、业务状态和下一步说明拼成最终通知，再交给指定回复或 AI 对话。

**注意事项**：变量为空时会影响文案可读性；对可选字段应给出默认文本或先使用判断器分支。

### 变量更新（`variableUpdate`）

![变量更新节点面板](./images/workflow/nodes/variable-update.png)

**用途**：更新全局变量或指定节点输出的值。

**关键配置**：选择目标变量，设置赋值、追加或其他支持的更新方式，并指定更新值。

**主要输出**：更新后的值可供后续节点引用。

**示例**：在循环中累积处理结果，或根据判断结果更新全局业务状态。

**注意事项**：只更新本流程内明确约定的变量；并行分支同时更新同一变量时需避免依赖执行顺序。

### 文档解析（`readFiles`）

![文档解析节点面板](./images/workflow/nodes/read-files.png)

**用途**：读取用户上传的文件链接并提取可处理的文本内容。

**关键配置**：传入文件链接列表，通常来自流程开始节点的用户文件输出或其他受控文件节点。

**主要输出**：解析后的文本或文件处理结果。

**示例**：用户上传制度文件 → 文档解析 → AI 对话进行摘要或问答。

**注意事项**：先在系统配置中开启用户文件能力；文件格式、大小和解析结果受运行时解析能力限制，失败时应提示用户换文件或重试。

## 工具与代码节点

### 工具调用（`tools`）

![工具调用节点面板](./images/workflow/nodes/tool-call.png)

**用途**：让模型根据用户问题自主决定是否调用挂载工具，并在工具结果返回后继续推理。

**关键配置**：配置模型、系统提示词、用户问题与可选历史。通过紫色工具锚点挂载工具节点。

**主要输出**：模型的最终回答和上下文。

**示例**：工具调用节点挂载“查询天气”和“查询图书目录”工具，由模型根据问题选择调用。

**注意事项**：只有正确挂载的工具才会注册给模型；工具描述、输入参数和返回结构要清楚，否则模型无法稳定选择工具。

### 停止工具循环（`stopTool`）

![停止工具循环节点面板](./images/workflow/nodes/stop-tool.png)

**用途**：某个工具执行完后立即停止工具调用循环，并以该工具结果结束处理。

**配置与连线**：将目标工具节点的普通下游连接到本节点。

**注意事项**：仅在画布已经存在工具调用节点时可添加；不要把它作为普通业务流程的独立结束节点。

### 工具参数（`toolParams`）

![工具参数节点面板](./images/workflow/nodes/tool-params.png)

**用途**：覆盖或补充工具调用所需的输入参数。

**关键配置**：定义工具参数名、类型、说明和变量来源。

**示例**：把当前用户 ID、默认知识库 ID 或上游提取的城市作为工具参数。

**注意事项**：仅在存在工具调用节点时可添加；参数名必须与工具实际 schema 一致。

### 代码运行（`code`）

![代码运行节点面板](./images/workflow/nodes/code.png)

**用途**：在受限运行环境中执行脚本，处理复杂转换、计算或结构化数据。

**关键配置**：添加输入参数；选择当前运行环境支持的语言；编写返回对象；在输出中声明需要传给下游的字段。

**主要输出**：代码返回对象中的动态字段、完整响应数据和错误信息。

**示例**：把接口返回的数组去重、筛选和重组为适合 AI 对话或表格展示的对象。

**注意事项**：不要将它当作任意系统命令入口；可用依赖、网络能力和执行时间均受沙箱限制。`return` 对象的 key 必须与配置的输出字段一致。

## 控制流节点

### 判断器（`ifElseNode`）

![判断器节点面板](./images/workflow/nodes/if-else.png)

**用途**：根据变量、文本、数值或布尔条件选择一个后续分支。

**关键配置**：配置条件组、比较方式和默认分支；条件左值通常引用上游输出。

**主要输出**：命中的分支从对应右侧出口继续。

**示例**：判断知识库搜索结果是否为空；为空时回复“未找到资料”，否则交给 AI 对话生成答案。

**注意事项**：为未命中任何规则的情况保留默认分支；比较前确认变量实际类型，避免字符串与数值混用造成误判。

### 循环节点（`loopRun`）

![循环节点面板](./images/workflow/nodes/loop.png)

**用途**：在容器内按数组元素逐项处理，或按条件反复执行。

**关键配置**：选择数组循环或条件循环；数组模式传入数组；配置需要从容器内部聚合出来的输出。

**主要输出**：`循环结果数组`和错误信息。

**示例**：遍历多个文档，逐个解析并抽取标题，最后聚合所有标题。

**注意事项**：循环体内应从“循环体开始”继续；条件循环必须有清晰的“跳出循环”路径，避免无限循环；不要在循环中执行成本不可控的外部调用。

### 循环体开始（`loopRunStart`）

![循环体开始节点面板](./images/workflow/nodes/loop-start.png)

**用途**：循环容器内每轮执行的固定入口。

**主要输出**：数组模式的`当前下标`和`当前元素`；条件模式的`当前循环次数`。

**注意事项**：由循环容器自动管理，不能删除。数组下标从 0 开始，条件循环次数从 1 开始。

### 跳出循环（`loopRunBreak`）

![跳出循环节点面板](./images/workflow/nodes/loop-break.png)

**用途**：结束当前循环容器，阻止后续轮次继续执行。

**配置与连线**：放在循环容器内部，并由判断器或其他条件节点连接到它。

**示例**：当找到第一个符合条件的记录后跳出循环。

**注意事项**：只能在已有循环节点时添加；放在容器外没有意义。

### 并行执行（`parallelRun`）

![并行执行节点面板](./images/workflow/nodes/parallel.png)

**用途**：对输入数组的多个元素并行执行容器体，并汇总结果。

**关键配置**：输入数组；最大并发数；单轮报错重试次数；容器内聚合输出。

**主要输出**：`成功结果`、`完整结果`和整体完成状态（全部成功、部分成功或全部失败）。

**示例**：并行解析多份相互独立的文档，再汇总每份文档的处理结果。

**注意事项**：并发数越大，对模型、HTTP 接口和数据库的压力越高；容器内应避免写同一个可变全局变量。

## 动态节点

动态节点不在基础功能列表中写死配置。编辑器会从“系统工具”“我的工具”或“可调用的应用”目录取得摘要，再请求服务端生成完整节点 schema。因此文档只能说明通用用法，具体输入输出以选中节点的表单为准。

### 单工具实例（`tool`）

![单工具实例（当前时间）节点面板](./images/workflow/nodes/tool-current-time.png)

**用途**：调用一个系统工具、HTTP/MCP 工具或其他已配置工具。

**使用方式**：在工具目录中选中工具后添加；若需要模型自主选择，挂载到“工具调用”节点的工具锚点；若要固定顺序执行，则按普通流程连线。

**注意事项**：检查工具参数、鉴权配置、超时和返回字段；只添加已审核、权限范围明确的工具。

### 工作流工具（`pluginModule`）

> 取图时的“我的工具”目录没有已发布工具实例。选中当前可访问的已发布工作流工具后，编辑器会根据其输入输出 schema 生成该节点面板。

**用途**：将已发布的工作流工具作为当前流程的一个可调用节点。

**使用方式**：从“我的工具”选择已发布工具，填写其 schema 暴露的参数，再引用输出字段。

**注意事项**：上游工作流工具修改输入输出契约后，应同步检查所有引用它的工作流。

### 子应用（`appModule`）

> 取图时没有可添加的子应用实例。选中当前可访问的已发布应用后，编辑器会根据该应用公开的 schema 生成对应字段。

**用途**：调用已发布的应用或智能体能力。

**使用方式**：从“可调用的应用”选择目标应用，按其动态 schema 传入参数，并消费返回值。

**注意事项**：目标应用必须已发布且当前用户有访问权限；跨应用调用时需明确输入输出边界，避免形成循环依赖。

### 自主 Agent（`agent`）

> 该节点由对话 Agent 编辑器生成，不在普通工作流“添加节点”菜单中出现；本文未附该编辑入口的截图。

**用途**：对话 Agent V2 的内部工作流表示，由 Agent 表单编译成系统配置、流程开始和 Agent 等固定结构。

**注意事项**：它不属于基础节点菜单中的可直接创建节点。日常配置请使用对话 Agent 编辑入口，不要手工把普通工作流 JSON 改成 Agent 节点结构。

## 当前不作为可用节点编写的类型

`toolSet`、`pluginConfig`、`pluginInput`、`pluginOutput` 等仍处于计划或未完整实现状态；旧循环容器、旧应用调用及占位节点已被排除。它们不会出现在本文的可用节点说明中，也不应被用于新建工作流。
