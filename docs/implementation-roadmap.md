## 2. 主对话实施顺序

```text
H0 契约与基线
 -> H1 Run Store 与 Harness Kernel
 -> H2 工具与沙箱
 -> H3 Context、Memory 与 Completion
 -> H4 Plan、Steer 与三个 Profile
 -> H5 前端与协议切换
 -> H6 硬删除与数据库迁移
 -> H7 Provider 额度治理与持久上下文投影
```

阶段状态、任务清单、退出条件和测试矩阵只在 Harness SSOT 更新，本文不复制，避免两份进度不同步。

## 3. 跨模块依赖

- 主对话调用知识库时复用知识库 ACL 和检索服务，不接管知识库数据所有权。
- 主对话调用工作台智能体时使用稳定委派协议，不读取工作流内部节点或调度状态。
- 演示文稿、校园和面试三个内置助手通过 preset/origin 接入主对话 Harness；工作台 Agent/toolCall 的函数循环只复用部分传输、压缩和结果存储能力，不能据此宣称具有主对话 Worker 恢复能力。
- 沙箱、用户文件和 Artifact Service 为主对话与工作台共用基础设施，但各自通过独立 Profile/Policy 控制权限。
- Java 用户、组织、角色和业务系统是身份与业务回执事实源。
- 数据库迁移、代理和部署变更必须遵守仓库 `AGENTS.md` 与本地热更新文档。

## 4. 共同验收门禁

每条开发线至少满足：

1. 目标行为有明确事实源和接口契约。
2. 权限、登录保护和代理配置没有被放宽。
3. 副作用有服务端校验、幂等、确认和真实回执。
4. 前后端状态来自同一持久化事实源。
5. 有定向自动化测试；用户交互变化完成真实浏览器验证。
6. 文件产物经过内容、格式和必要的渲染检查。
7. 失败、部分完成和基础设施错误不会伪装成成功。
8. `git diff --check` 通过，且未修改用户无关工作。

## 5. 维护规则

- 新功能首先找到所属开发线；不得在本文新建一套详细执行计划。
- 跨模块依赖变化更新本文，模块内部变化更新对应事实源。
- 主对话状态只更新 Harness SSOT，禁止复制阶段表到其他文档。
- 已完成且被事实源吸收的调查稿和交接稿删除，通过 Git 历史追溯。
